> 状态：草案 / 评审中

## 1. 项目介绍

### 1.1 背景

在个人与工作场景中，我们往往同时订阅了多个付费服务：大模型 API（如 OpenAI、Claude、Gemini）、各类 SaaS 工具、流媒体会员、云资源套餐等。这些订阅的**到期时间、扣费周期、价格**分散在不同平台的通知邮件里，极易被遗忘，导致：

- 忘记续费造成服务中断（如关键 API Key 失效）；
- 忘记取消造成持续自动扣费，产生不必要的开支；
- 无法从全局视角掌握"本月/本季度订阅支出"与"即将到期的服务"。

### 1.2 产品定位

**exp-track** 是一个**本地优先的订阅到期追踪与可视化网站**。用户将所有订阅信息集中录入，系统基于到期时间进行统一管理与可视化展示，帮助用户：

- 在一个看板中掌握所有订阅的剩余天数、状态与费用；
- 在订阅即将到期前得到提醒；
- 通过图表直观了解订阅支出分布与趋势。

> **阶段定位（MVP 第一阶段）**：当前版本为 **MVP 测试阶段**，**优先解决个人用户**的订阅管理需求。本阶段**不纳入小型团队的多人协作场景**（无多账户、无共享/权限体系），相关能力列入后续规划。部署方式上同时提供「快速部署（无需容器）」与「稳定部署（MySQL）」两种路径，以最大化个人本地使用的便利性。

### 1.3 目标用户

- **本阶段核心用户（个人）**：
  - 个人开发者、独立创作者：管理大模型 API（如 OpenAI、Claude、Gemini）/ 工具类订阅；
  - 任何希望掌握自身订阅支出与到期情况的个人用户。
- **暂不在本阶段范围**：小团队管理员（团队共用订阅的多人协作、共享看板、权限管理），详见 1.6 范围说明。

### 1.4 核心特性

| 特性 | 说明 |
|------|------|
| 订阅录入 | 手动添加订阅：名称、类别、价格、计费周期（月/季/年）、开始日期、到期日期、是否自动续费、备注。 |
| 到期看板 | 以卡片 / 列表形式展示所有订阅，按"剩余天数"排序，突出临期与已过期项。 |
| 状态标识 | 已过期 / 7 天内到期 / 30 天内到期 / 充足 四档状态，颜色区分。 |
| 可视化统计 | 用图表展示：订阅月度支出分布、类别占比、未来到期时间轴。 |
| 临期提醒 | 基于到期时间，在前端以醒目标识提示即将到期的订阅（MVP 阶段以页面提示为主，预留通知扩展）。 |
| 灵活部署 | 提供**快速部署**（无容器、嵌入式数据库，开箱即用）与**稳定部署**（MySQL 环境）两种方式，数据均保存在本地，无第三方云服务依赖，保障隐私。 |

### 1.5 技术架构概览

项目采用**单仓库前后端分离**结构：

- **前端**：Vue 3 + Vite + TypeScript，使用 Pinia 状态管理、Vue Router 路由、ECharts 图表、Day.js 时间处理。
- **后端**：Express 5 + TypeScript，提供 REST API，统一响应信封契约。
- **数据库（可切换）**：
  - **快速部署**：使用嵌入式数据库 **SQLite**（文件型，无需安装数据库服务，零外部依赖）；
  - **稳定部署**：使用 **MySQL 8.0**（通过 Docker Compose 或直接连接既有 MySQL 实例）。
  - 后端通过数据访问层（DAL）抽象屏蔽两种数据库的差异，业务代码不感知底层数据库类型。

### 1.6 范围说明

- **本期（MVP 第一阶段）范围**：
  - 面向**个人用户**的订阅增删改查、到期看板、基础可视化统计；
  - 两种本地部署方式（快速部署 / 稳定部署）；
  - 单用户、单实例的本地数据存储。
- **非本期（MVP 第一阶段）范围**：
  - **小型团队多人协作**：多用户账户、登录鉴权、共享看板、成员权限管理、团队协作；
  - 邮件 / 短信 / Webhook 主动推送提醒；
  - 订阅自动抓取（对接第三方账单 API）；
  - 移动端原生应用。

## 2. 部署要求

产品需支持**纯本地部署**：数据保存在用户自有环境，不依赖任何第三方云服务，以保障隐私。为兼顾不同用户的机器环境，MVP 阶段要求提供两种部署模式：

| 部署模式 | 适用场景 | 容器环境 | 数据库 | 复杂度 |
|----------|----------|----------|--------|--------|
| **快速部署** | 个人本地试用，机器无 Docker / 容器，希望开箱即用 | 不需要 | SQLite（文件型，零依赖） | 低 |
| **稳定部署** | 具备 MySQL 环境（本机或已有实例），追求数据稳定性与可维护性 | 可选（推荐 Docker） | MySQL 8.0 | 中 |

**要求明细：**

- 两种模式共用同一套前端 / 后端代码，底层数据库类型对用户与业务代码透明，通过配置切换；
- 个人用户**默认推荐快速部署**，无需安装任何数据库服务即可运行，数据以单文件形式存放，便于备份与迁移；
- 当数据量增长或需要数据库级管理时，可平滑切换至稳定部署；
- 部署过程对用户友好，安装 / 配置 / 启动步骤应最小化，降低个人本地使用的门槛。

> 具体的安装、配置与启动命令（如依赖安装、环境变量填写、Docker 编排、端口与故障排查）属于工程部署手册（README）范畴，不在本文档展开；开发 / 运维人员请参考仓库 README 与相关部署文档。

## 3. 后续规划

### 3.1 MVP 第一阶段待细化

- 订阅编辑 / 删除的交互细节与字段校验规则；
- 临期提醒的阈值配置与通知渠道扩展；
- 可视化图表的具体维度与交互；
- 数据导入 / 导出（CSV、JSON）能力；
- 快速部署 ↔ 稳定部署之间的数据自动迁移工具。

### 3.2 第二阶段（非本阶段，候选）

- **小型团队多人协作**：多用户账户、登录鉴权、共享看板、成员权限管理、团队协作（本阶段明确不在 MVP 范围内）；
- 邮件 / 短信 / Webhook 主动推送提醒；
- 订阅自动抓取（对接第三方账单 API）；
- 移动端原生应用。
